## Outcome and boundary

The original candidate can be reconstructed from 20 small UTF-8 files in this folder plus 31 byte-identical files already committed in `jfcaicedoobando-arch/elogistix` at `5b2294da3badd117fb498cbf4daac278bd291bf0`. Nineteen files are required runtime/build/test inputs; the twentieth is the original dependency inventory. The selected originals total 119,472 bytes. The assembly helper and manifests are newly prepared transfer tooling.

This proposal is for an isolated draft branch and a local browser run in the saved CLOUD environment. It does not modify the ERP runtime, touch a database, merge into main, deploy, or authorize external communications. No Git objects have been created by this review.

The source identity is the original ZIP, not a historical candidate commit: `cartera-batched-portable-v1.zip`, 4,659,524 bytes, SHA-256 `5f0d2a40c9bae2152aad60f964027456fe2366229b37ce9a4a7d69a99b9bde02`. ## Browser acceptance sequence

Use one tab and sequential runs. Record browser version, OS, timezone, viewport, available RAM, exact branch/base commits, dependency versions, console errors and requests. Only local loopback/data requests should occur. Record OS-level process-tree memory if supported; main-thread `performance.memory` does not measure all workers. Do not report a browser RSS cap as enforced by the JavaScript harness.

1. Complete regular 120 rows with batch size 50: reference 17 pages, folios QA-00001..QA-00120 exactly once and in order. Save browser-generated PDF and JSON report; inspect pages 1, 8, 9 and 17.
2. Complete Unicode 121 with batch size 50: reference 35 pages. Check all ten columns per row, FIN-Ñ, Greek/Cyrillic, three currencies and each summary exactly once.
3. Cancel before start; no final PDF should be offered. Re-run 120 successfully.
4. Cancel 5,001 during render using the 5.5 s mode and also exercise manual/double Cancel. No partial/old result may be enabled.
5. Cancel during merge using 120/50 ms. If it finishes before the abort actually occurs, mark that case unexercised and retry with 5,001 to reach the merge cancellation window. Do not count a completed run as a cancellation pass.
6. Re-run 120 after both cancellation phases. Confirm controls recover, no stale download occurs and actual browser worker targets terminate. A protocol counter of zero is not proof of OS memory release.
7. Complete regular 5,001 at batch size 500 with original 150-second cancellation timeout. Expected job structure: empty CxC, ten 500-row CxP jobs and one 1-row job; then one merge worker. Node reference is 602 pages, 2,557,643 bytes, approximately 73 s; timing, memory and exact PDF bytes are not a browser requirement or prediction.
8. Save browser-produced PDF/report. Independently verify 5,001 unique folios in order, every page's global number, complete cell text/bounds, both summaries once and no clipped body/footer. Inspect pages 1, 2, 62, 122 and 602 as well. A screenshot alone is insufficient.
9. Re-run 120 after the large case, then close the tab and stop the loopback server. Retain test reports, downloaded PDFs, dependency/build inventory and console/network evidence.

The old Node verification scripts in the ZIP require per-batch PDFs or original absolute paths; do not blindly run them on a browser PDF and claim equivalence. Use an independent browser-output verifier with the actual downloaded file and the copied fixture. If a stage fails, report the exact failed/unrun gate without substituting Node evidence or production ERP behavior.
