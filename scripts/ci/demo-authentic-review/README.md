# Isolated authentic producer/registry review

Scope: real proposed identity producer, origin verifier, bridge, scheduler registry and context issuer executed against synthetic PostgreSQL 17.6 tables. Validation code is preserved; tenant and fixture literals are replaced with wholly synthetic constants. No historical organization is contacted or operated on. This is not a full financial-engine integration or a production authentication test.

The public core function is an explicit fail-closed ownership-metadata fixture that always raises. It is never invoked. It establishes only the catalog owner used by the actual registry implementation; it does not establish historical core behavior, human identity, R3 deployment or production permission equivalence. No auth.uid success/null double is installed. The genuine CRM trigger's auth branch remains unresolved if unexpectedly invoked; the actual identity helper's inactive-insert protocol avoids that branch.

Compatibility roles anon/authenticated/service_role are NOLOGIN in the new disposable cluster, without grants, passwords or application access. The bootstrap superuser supabase_admin creates only disposable roles and the database. All candidate/schema installation, producer, registry and assertions run as postgres NOSUPERUSER NOBYPASSRLS NOCREATEDB NOCREATEROLE NOINHERIT. Runtime checks enforce both identities. Neither identity is a real backend principal. Only owner scheduler preparation is positively exercised; actual RPC transport is required to reject this unqualified connection.

Synthetic fixture constants use tenant 00000000-0000-4000-8000-000000000001, Synthetic Customer/Contact/Supplier labels, empty RFC and phone, example.invalid email addresses and explicit UUID mappings. Original contact data is not distributed. source-pins.json preserves upstream checksums and marks adaptation; inputs.json freezes runnable SQL. The manifest digest was regenerated for synthetic-catalog.json's compact JSON representation.

The same-repository draft-PR workflow is restricted to branch fix/demo-authentic-producer-review-20261015 and exact pull request HEAD checkout. No secrets, production environments, network database DSNs, deployment or financial operations. Docker uses a digest-pinned image, network none, no TCP listener, no ports, no bind mounts and scrubbed child-process environment. PostgreSQL runs through its internal socket. Owned container and anonymous volumes are removed and absence verified.

Covered SQL assertions: authentic receipt origin and idempotency before financial materialization; current supplier/shipment/category and immutable receipt bindings; job/policy drift; deleted/banned sponsor, missing membership/role, expired transport and inactive synthetic organization; context snapshot issuance; receipt from policy A cannot authorize B; unqualified RPC transport denial; zero financial DML; transaction rollback leaves no provenance. Positive producer and context checks use the actual proposed implementations, not success-returning doubles.

Current state before CI: SQL/Docker NOT_RUN. Offline harness tests pass. A successful Actions run may report only PARTIAL_AUTHENTIC_PRODUCER_ONLY. Still untested: durable dispatch, real PostgREST authentication and commit ACK, full main schema/ACL equivalence, financial engine/checkpoint, authenticated human regression and multi-session concurrency. Failure logs are retained, and SQL success markers are mandatory.
