# Minimum private contract for a future operational comparator

Status: **specification only; NOT_ADMITTED**. The parent already holds the captures and can provide the relevant existing projections in the private coordination thread. This document defines those projections and their review rules; it does not ask the user to collect them again. No captured value, instance name, object identity, observed hash, history row or contact belongs in this public document, repository, PR, workflow input or artifact.

The parent can instead retain the complete projection files locally and run `offline_review.py` using a private file map, returning only its sanitized report and any specifically needed review slice. See the README for the offline invocation and validator requirements. No full instance transfer to a child checkout is needed. Raw private deparse/binding evidence remains separate from the strict projection bundle.

The transaction-bound operational comparator, event-policy admission and executable registration envelope are still missing. `evidence.ingest()` checks projection coherence; `comparator.compare()` checks permitted deltas between supplied complete bundles. Both always return NOT_ADMITTED. An offline match does not approve the preimage, authenticate its completeness or bind it to a locked execution transaction. `envelope.render_review_proposal()` always raises before payload execution. None of these results changes the LAB renderer or admits a target.

The bundle accepted by `evidence.ingest(bundle, validate_projection=...)` has exactly the nine required keys `kind`, `discovery`, `catalog`, `drizzle_history`, `supabase_manifest_before`, `supabase_pages`, `supabase_manifest_after`, `sequence_state`, `activity`. Optional `claims` accepts only the existing `transport_verified` and `ddl_acl_window_open` booleans; those values confer no approval, transport proof or window. No other admission token, policy receipt or bypass field is defined here.

Every projection envelope requires the five fields `kind`, `section`, `admission`, `capture`, `result`; its kind is `crm-operational-evidence-v1` and admission remains NOT_ADMITTED. `capture` has nine required fields: `captured_at`, `statement_at`, `database`, `database_oid`, `backend_pid`, `snapshot`, `xid_if_assigned`, `user`, `session_user`. A trusted offline schema validator must validate each full projection and return exactly True; input claims cannot supply that validator. Review slices below are not a complete bundle until all required sections are present. Preserve the original complete capture privately and do not discard unmatched nodes.

3. `catalog.result.roles`: all relevant execution/session, owner, ACL-grantee/grantor and membership-closure roles. Match discovery names/identities, owners, argument/return types, column numbers/types and inheritance links to the catalog nodes. No same-name object may silently replace an observed identity.

Verify its source commitments against the immutable public helper source contract, its null/config flags and all semantic function attributes against that contract, its owner against the measured owner role, and every trigger link against the canonical trigger contract. ACLs must be explicit and limited to the owner plus the optional permitted service EXECUTE entry, with the expected grantor and no grant option. Capturing BYPASSRLS or SECURITY DEFINER metadata is not approval of that execution mode.

Supply every captured `eventTrigger` node with all seven fields `oid`, `evtowner`, `evtfoid`, `evtname`, `evtevent`, `evtenabled`, `evttags`, and each associated full `function` node, owner/ACL/membership/configuration/dependency context and any reachable function nodes. Do not select only the public handler that happened to match an upstream source hash. Every active event must be classified for the exact engine, event/tag filter, enabled mode and session replication mode, including recursive commands; exclude none without a demonstrated reason.

Public upstream body verification proves source equality only. Public-handler fixture passes do not validate other callbacks or external effects. The actual policy still requires privately reviewed installed identities, owners, effective privileges, configuration/search-path resolution, extension/dependency binding and a closed call/effect graph, including procedural late binding and dynamic SQL. `pg_depend` does not close that graph. Unknown calls, privileged transitions, notifications/consumers, queue writes, external effects or unbounded behavior block admission. No disabling events, changing replication mode to suppress them, adding roles/grants or substituting a weaker handler is part of this contract.

The permitted persistent transition remains only the canonical helper ACL changes plus its separately specified single Drizzle registration/default-sequence effect. No event-driven persistent DDL/DML expansion is approved here. Any notification behavior must have an independently bounded policy and isolated evidence; an observed listener or public fixture is not evidence about real consumers. The event metadata and all source/configuration/dependency commitments must remain unchanged throughout.
