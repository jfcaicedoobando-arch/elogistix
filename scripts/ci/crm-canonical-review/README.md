## Serial-ledger wrapper protocol

`direct_wrapper.py` renders exactly one top-level DO, with no database connection, DSN, application CLI or operational mode. It only admits a measured PG17.6 non-superuser disposable `crm_acl_fixture_*` contract. `PROPOSAL_direct_ledger_wrapper.sql` remains unchanged and aborts. A new private envelope, transport proof and DDL/ACL window are still required for any real route; no R3 approval is reused.

The renderer decodes the canonical file's exact bytes from hexadecimal and checks SHA256 and the UTF8 roundtrip before EXECUTE. The caller must already have established statement_timeout in the same session; the DO checks it is positive and at most 20 seconds. A successful DO does not prove COMMIT if a transport leaves an outer transaction open.

Lock order is existing Drizzle ledger SHARE ROW EXCLUSIVE NOWAIT, existing Supabase ledger SHARE NOWAIT, then CRM table SHARE UPDATE EXCLUSIVE NOWAIT. The captured full ordered histories, scoped semantic catalog, role memberships, sequence relation/ACL/owned-by/default/index metadata, events and their functions are checked. Lab admission rejects event triggers, ledger triggers/rules/policies/inheritance, unsupported columns or defaults, additional/referencing constraints, and unsupported sequence conventions. Only the verified builtin serial nextval with increment/cache 1 and no cycling is supported. Registration omits id and uses the actual INSERT RETURNING value; no explicit id, setval, grant or Supabase write exists.

An exact registered row requires the complete owner-only target state and preserved original history; it is verified without executing the payload or advancing the sequence. Other history, same-hash/other-time, same-time/other-hash and catalog drift reject. Every terminal check runs after insertion. On failure PostgreSQL rolls back rows and ACLs; nextval may leave a gap. Fresh independent reads reconcile an uncertain response. A newly rendered verification uses the observed sequence state; blindly resending the old envelope is not the recovery protocol.
