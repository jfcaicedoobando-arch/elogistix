# Isolated runtime acceptance plan — NOT EXECUTED

Scope: one separately authorized disposable PostgreSQL instance and synthetic tenant/obligation set. No production/staging company data, network endpoints, real fiscal operations, real credentials, Docker or migration execution in this preparation. Stop and retain HOLD if an authorized isolated instance, driver, issuer or business fixture is unavailable.

1. Inventory exact database/runtime and approved pre-existing access without displaying secrets. Pin driver package/source and verify same physical socket from first claim BEGIN through business COMMIT; prohibit multiplexing, auto-reconnect, retries and pipeline. Instrument server backend PID/start, connection epoch and protocol ReadyForQuery, not client-local inferred state. Empty configuration must open zero sockets.
2. Compile review SQL in disposable schema. Verify PK/FK, binding equality, trigger rejection of UPDATE/DELETE/TRUNCATE and unique canonical tuple. Do not install grants or roles. Test behavior under the already-authorized principals; missing privilege isolation is HOLD, not permission to create it.
3. Connect issuer resolver to synthetic authenticated scheduler evidence. Persist with ISSUE_SQL in a separately acknowledged issuer transaction. Reissuing the same obligation with changed context, snapshot, retry ID or canonical version must not add a new row. Changing occurrence must require independently authorized evidence. Adversarial resolver/request substitution must fail before write.
4. Persist one exact dispatch consumption through `consume(driver,'dispatch',...)` and commit. Test no dispatch, mismatched binding/context/tenant/deployment and forged context. None can win ingress. No SELECT-based receipt recovery.
5. Start multiple independent real connections racing the same obligation; exactly one new ingress INSERT may return a row, and only its COMMIT-confirmed live caller may open businessTX. Repeat with two processes and contexts reissued for same canonical obligation. Verify the losing insert returns zero and no business starts.
6. Drop connection during insert, before claim COMMIT, after server claim COMMIT but before its response, and immediately after acknowledgment. Confirm unknown ACK always starts zero business and restart does not regain the consumed right. If prior claim rolled back, do not automatically retry it in the application; preserve administrative quarantine semantics.
7. Bind authentic prepare+execute+checkpoint SQL to an isolated fixture; validate complete financial projection and receipts with genuine assertion helpers. Induce failure after each financial effect; all business effects roll back together but ingress consumption remains. No callback makes external network calls or uses a second database session.
8. Lose business COMMIT response, kill executor, then run read-only RR reconciliation with fresh authenticated read access. Verify no recovery path invokes business. Deliver delayed duplicates/original ingress before and after uncertainty. Every duplicate still crosses the durable gate.
9. Force socket replacement/backend switch/reconnect at every phase, wrong ReadyForQuery state, synthetic command-tag corruption, concurrent query and unconfirmed close. Verify no next SQL statement and no retry after detected uncertainty. Independently audit actual no-replay behavior; metadata-only checks cannot prove it.
10. Simulate restore/failover that could lose the ledger; enforce global stopped executor until reconciliation. Demonstrate durable accepted-failover domain, not merely synchronous_commit setting. Claim retention is permanent.
11. Acceptance artifacts: exact source/version pins; SQL compile logs; physical wire/backend timeline; concurrency winners; fault matrix; authentic financial/reconciliation evidence; issuer/auth/ACL/bypass review. All evidence must refer to same immutable build. Any missing item => HOLD. Activation remains a separate decision and is outside this plan.
