# CI reconstruction — 2026-11-09

`.github/workflows/ci.yml` is the only active workflow. It runs for pull requests to `main`, pushes to `main`, and manual dispatch. The required check is named **CI**.

## Required checks

- ESLint with zero warnings, a fresh TypeScript check, Knip and dependency consumer contracts.
- Production build, existing bundle-size and sourcemap limits, and real PDF pagination regressions.
- The entire normal Vitest suite, with file isolation and two workers per runner. Fourteen native shards are the initial configuration; manual 8/10/14 inputs support comparison on the same commit.
- Offline Node/Python contracts, plus actionlint.
- Secret scanning of history/diff and final changed file contents.
- On database changes: static schema/manifest checks, all ordered migrations in an empty disposable local PostgreSQL instance, integrity checks and the six minimum RLS suites (tenant isolation, financial behavior, cross-tenant mutations, roles, anonymous denial and policy linting).
- On Edge changes: canonical adapter typechecks and deployable entrypoint checks, then Deno tests with explicit operation/resource leak checks.

The final check requires every mandatory job to succeed. Conditional jobs may be skipped only when the area decision is explicitly `false`. It also verifies the exact union of executed unit files and cases, rejecting missing, duplicated, skipped, retried or failed cases.

Dependency caches include OS, architecture, Node/Bun version files, package manifest and lockfile. Every job still verifies runtime versions and executes `bun install --frozen-lockfile --ignore-scripts`. TypeScript build state is not restored across runs. Tests use no production credentials or remote database.

## Extended checks run explicitly

The previous full database workflow took roughly 8–12 minutes. Extended concurrency, historical replay and full SQL behavior are retained as commands, outside the fast automatic checks:

```bash
bun run db:verify -- --all
bun run test:coverage
bun run test:perf
bun run test:pdf
bun run test:visual
bun run e2e:check
bun run e2e
bash scripts/ci/dependency-audit-manual.sh
```

E2E uses the existing dedicated test environment and `.env.e2e.example`. Provision only approved test identities. `scripts/ci/database-full.sh` preserves the extended former SQL recipe; it requires an empty disposable local PostgreSQL 17 service, its container ID in `POSTGRES_SERVICE_ID`, a matching PostgreSQL client, Docker and Node. It must never point to a production service.

Frozen `.yml.txt` sources in `docs/ci/workflow-archive/reset-20261109/` support historical review contracts and recipe recovery. GitHub does not execute them. Current CI tests target the new active workflow and its fail-closed result checker. Tests that only asserted the removed orchestration were replaced; business tests and migration source bytes remain intact.
